## 复核问题与修复

### 1. 真正应用 prosemirror_step，不丢失作者内容、不写 "applied"

- 新增 `backend/app/domain/prosemirror.py`：提供 `empty_doc_content()`、
  `empty_doc_hash()`、`apply_prosemirror_steps(base, operations)`。
  - 首稿以规范化空 ProseMirror 文档 `{"type":"doc","content":[]}` 为基线。
  - 支持 `insert`/`replace`/`delete` 三类文档级最小解释器，操作按序应用到
    基线文档并返回规范化 JSON，绝不写入占位 `"applied"`。
  - 解析失败或遇到不支持操作抛 `AppError`，不静默丢弃作者内容。
- `backend/app/domain/manuscript.py::commit_scene_change_set`：由原来写
  `"applied"` 改为把操作真正应用到基线内容并落盘。
- `backend/app/domain/change_sets.py::create_author_change_set`（首稿分支）：
  在建 `SceneDraftArtifact` 前先 `apply_prosemirror_steps`，草稿内容为真实
  应用结果而非空文档。

### 2. 提交时锁定场景并重新校验当前 accepted 基线，拒绝过期 ChangeSet

- `change_sets.py::commit_change_set`：先 `with_for_update()` 锁定场景行，
  再取当前 accepted 修订 id。
  - 根 ChangeSet：若场景在首稿创建后已被接受过版本则拒绝
    （`SCENE_STALE`）。
  - 非根 ChangeSet：判断 `base_scene_revision_id == 当前 accepted`，不匹配
    视为过期 ChangeSet 拒绝（`SCENE_STALE`）。
- `manuscript.py::commit_scene_change_set`：作者接受提交时，非根物化修订
  直接置为 accepted，使 accepted 指针随每次提交推进，基线校验才有意义。

### 3. 首稿创建和物化时锁定场景，确认无 accepted，正确更新 ChangeSet 状态

- 创建：`create_author_change_set` 首稿分支先 `_lock_scene`，再确认无
  accepted 版本（`_has_accepted_revision`），校验失败抛
  `SCENE_STATE_INCOMPATIBLE`。
- 物化：`commit_change_set` 锁定场景后，若根首稿且场景已有 accepted 版本则
  拒绝（`SCENE_STALE`）。
- `drafts.py::commit_scene_draft`：修复了原“空条件分支”死代码，改为：若
  场景已有 accepted 版本直接抛 `SCENE_STATE_INCOMPATIBLE`，再置草稿为
  accepted。
- ChangeSet 状态：提交成功后 `change_set.status = "committed"`（根与非根
  都在 `commit_change_set` 内统一置位）。

### 4. handoff 读取必须同时满足 accepted、active、in_sync 且来源版本匹配当前 accepted

- `api/chapters.py` 新增 `_current_valid_handoff`：先取章节当前 accepted 修订
  指针（无则返回 None），再要求 `status=active`、
  `entry_handoff_status=in_sync` 且 `source_chapter_revision_id == 当前
  accepted id`。`get_chapter` 与 `get_chapter_handoff` 均改用它，绝不回退到
  旧 handoff 或最新修订。

### 5. ChangeSet 提交的幂等作用域必须包含 change_set_id

- `api/scenes.py::post_commit`：`execute_command` 的 resource_scope 由
  `scene:{scene_id}` 改为 `scene:{scene_id}:changeset:{change_set_id}`，
  不同 ChangeSet 的同键提交互不干扰、不互相重放。

### 6. 补充并发、重复提交和内容落盘测试

- `tests/api/test_manual_changesets.py` 更新/新增：
  - 首稿草稿内容断言为真实应用结果（含作者文本）。
  - 根提交/非根提交内容落盘断言（非 `"applied"`、含作者文本）。
  - ChangeSet 状态提交后为 `committed`。
  - `test_nonroot_commit_rejects_stale_baseline`：推进 accepted 后旧基线
    提交被拒 `SCENE_STALE`。
  - `test_duplicate_commit_is_idempotent_and_single_revision`：同键重复提交
    只产生一条修订。
  - `test_commit_idempotency_scope_includes_change_set_id`：不同场景同键提交
    互不冲突。
- `tests/api/test_chapter_handoff.py` 新增：
  - `test_handoff_read_requires_source_matches_current_accepted`：旧 handoff
    来源不匹配当前 accepted 时返回 None。
- 新增 `tests/domain/test_change_set_concurrency.py`：
  - 场景行锁并发测试（第二会话持锁时首稿创建被语句超时阻塞，证明锁生效）。
  - 已提交首稿后再次创建首稿被拒 `SCENE_STATE_INCOMPATIBLE`。

## 复核问题 7-9（Codex 二次复核，已修复并测试）

### 7. manual_command_id 必须在首次幂等 claim 落库时生成；重放与过期接管复用原 ID

- `app/domain/idempotency.py::claim`：新键首次 claim 落库时生成并持久化
  `manual_command_id`（`str(uuid4())`）。重放（completed）与过期接管
  （processing + 过期）都直接复用首次生成的原 ID，绝不重新生成。
- `app/api/commands.py::execute_command`：`run` 签名改为接收
  `manual_command_id`（来自 claim 记录）并返回 `(response, result_ref)`；
  `complete()` 不再由其自行生成 ID，而是复用 claim 记录里的原 ID。
- `app/api/scenes.py` / `projects.py` / `volumes.py` / `chapters.py`：所有
  `execute_command` 的 `run` 闭包改为接收 `manual_command_id` 参数并返回二元组。
- `tests/domain/test_idempotency.py` 更新/新增：
  - `test_manual_command_id_generated_on_first_claim_and_reused`：首次 claim
    生成并持久化。
  - `test_manual_command_id_reused_after_expired_claim_takeover`：claim 后
    崩溃（processing + 过期）被接管后复用原 ID。
  - `test_manual_command_id_reused_after_complete_then_claim`：完成后再 claim
    复用原 ID。

### 8. 修复 Task 2 的 get_valid_entry：校验来源 ChapterRevision 为 accepted 且匹配当前 accepted 指针

- `app/domain/handoff.py::get_valid_entry`：新增校验：
  - 来源 `ChapterRevision` 必须存在且 `status == "accepted"`。
  - 来源修订必须等于该章节当前 accepted 指针（不匹配视为过期）。
  仍保留 active + in_sync + 链哈希匹配要求。
- `tests/domain/test_chapter_handoff.py` 新增：
  - `test_get_valid_entry_rejects_stale_source_not_current_accepted`：来源修订
    不再是当前 accepted 时返回 None。
  - `test_get_valid_entry_rejects_non_accepted_source`：来源修订未 accepted 时
    返回 None。
