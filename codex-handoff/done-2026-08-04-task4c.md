## 关键设计决策

1. **正式结构按类型区分**：`CanonFact`（属性/关系/事件/规则）、`TimelineEvent`
   （故事内时间/实体/地点）、`PlotThread`（伏笔/冲突线状态与计划回收位置）三张正式
   表；章节级 confirm 按候选 `candidate_type` 在同一事务写入正确结构，来源版本由
   候选与决策记录追溯。
2. **候选锁定 + 状态机**：`apply_canon_decisions` 按 `candidate_type` 在对应候选表上
   `FOR UPDATE` 锁定行，候选只能从 `pending` 一次性迁移到
   `accepted|rejected|deferred|discarded`；已决策/已丢弃候选拒绝再次决策，保证并发
   决策不互相覆盖。
3. **幂等指纹**：决策请求指纹包含作用域与全部决策内容（候选 id/类型/决策/别名）；
   同键同指纹重放、不同指纹 `IDEMPOTENCY_KEY_REUSE`（写入前拒绝）。
4. **作者命令身份**：作者确认提交使用 `manual_command_id` + API command fence +
   `source=author`（`generation_run_id=None`），不伪造 Worker 身份；候选提取阶段
   仍使用 Worker/agent 上下文。
5. **Canon 分支图**：独立 `CanonGraph`（真实 StateGraph），CanonAgent 节点只持久化
   候选（不写正式 Canon），`interrupt` 等待作者 confirm|reject|defer|cancel，提交
   节点经 `CommitGuard` 后调用 `CanonCandidateService.confirm_decisions`。
