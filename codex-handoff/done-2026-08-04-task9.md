## 验收脚本（`backend/app/acceptance/cli.py`）

- `reset clean`：从空库重建固定 fixture（drop/create 领域表 + checkpoint 表），输出双哈希与 fixture_hash；
- `reset preserve_history`：只清理临时数据（未决运行/事件/租约/未发布 outbox），权威与审计数据保留；
- `backup`：导出双哈希与表行数摘要（脱敏 JSON，无正文/密钥）；
- `restore`：校验备份双哈希与当前库一致，一致返回 0，不一致返回 1；
- `smoke-scene`：clean 重建 → 播种并接受章节 plan → 播种已接受场景基线 → 创建场景运行 → RunWorker.tick() 执行 → 断言 processed==1、到达 waiting_feedback/pending_clarification、事件序列 run_queued→结果事件；
- `feedback-regression`：v1-fixture 重建 → 播种基线 → 逐条执行 10 条反馈（非 canon 走 `_create_scene_run`+Worker；canon 走 `_run_canon_case`：场景级 Canon 运行 + Worker），逐条断言 final_status 与事件序列。
- 输出约定：JSON、脱敏、失败返回非 0 退出码；Fake model 语义明确标注，不宣称为真实模型证据。

### 排障记录（脚本自身问题，均已修复）

1. 无 BOM UTF-8 脚本被 PowerShell 5.1 按 ANSI/GBK 解析导致中文乱码与语法错误 → 加 UTF-8 BOM；
2. PS 5.1 向 `python -c` 传参剥掉代码内双引号（`print("x" % v)` 变成语法错误）→ 改写为临时 `.py` 文件后以文件路径执行；
3. .NET `Encoding.UTF8` 写 BOM 导致 `json.load(encoding="utf-8")` 报 BOM 错误 → 写入改用无 BOM UTF8 编码，读取用 `utf-8-sig`；
4. 超时探测 HTTP 状态为 null/0 未映射 → 补 `LLM_UNAVAILABLE` 分支；
5. 汇总判定用带空格的 `"ok": false` 正则漏判 `-Compress` 无空格 JSON → 改为 `"ok":false`。

### 错误处理（与 smoke 映射表一致）

- 超时/连接失败 → `LLM_UNAVAILABLE`（retryable=True）；
- 401/403 → `LLM_AUTH_ERROR`、400 → `LLM_INVALID_REQUEST`、404 → `LLM_ENDPOINT_NOT_FOUND`、
  429 → `LLM_RATE_LIMITED`、5xx → `LLM_SERVER_ERROR`；
- 响应非 JSON / 缺 `choices` / 内容不可解析 → `LLM_RESPONSE_INVALID`；
- 模型响应不合 `WritingOutput` schema → `LLM_RESPONSE_INVALID`（WritingAgent 包装 pydantic ValidationError）。

### 失败不写库（真实模型失败边界）

Provider 失败在 writing 节点上抛 `AppError(LLM_*)` → 图异常 → Worker fail-closed
（回滚事务）→ 运行置 `failed` + `run_failed` 事件 + `last_error_code`；链路测试断言
`scene_revisions`/`scene_draft_artifacts`/`canon_facts`/`timeline_events`/
`plot_threads`/`fact_candidates` 六张表运行前后无增量。

### 安全

日志、输出、交接文档或 Git；`http_client` 注入仅用于测试（MockTransport），
真实进程自建客户端。

## Provider 失败自动重试（2026-08-05 已实现并验证）

### 范围

在现有计划边界内，为 `DeepSeekModelProvider` 增加有限次 + 指数退避的失败自动
重试。仅对可重试错误重试；认证错误与结构化响应错误不重试；重试只发生在模型
出站调用层，不产生重复版本/候选/Canon/事件写入（保持幂等与 fencing 约束）。
未新增任务编号。

### 交付

| 文件 | 职责 |
| --- | --- |
| `backend/app/agents/model_provider.py`（修改） | 新增 `_RETRYABLE_CODES` 白名单（`LLM_RATE_LIMITED`/`LLM_UNAVAILABLE`/`LLM_SERVER_ERROR`/`LLM_UNKNOWN_ERROR`）；构造器新增 `max_retries`（默认 3）、`retry_backoff`（默认 0.5s）、`retry_jitter`（默认 0.1s）、`sleep`（测试注入）；`invoke_structured` 经 `_invoke_with_retry` 循环调用模型出站层，`_retry_delay` 计算指数退避（base*2^n + 抖动） |
| `backend/tests/agents/test_model_provider.py`（修改+新增） | `_provider` 默认 `max_retries=0`；新增 5 项：限流后成功（重试 1 次、出站 2 次、休眠 1 次）、耗尽 max_retries 后上抛（总尝试 max_retries+1）、认证错误不重试（单次）、结构化响应错误不重试（单次）、退避指数增长 |
| `backend/tests/runtime/test_real_writing_chain.py`（修改+新增） | `_real_provider` 关闭自动重试；新增重试幂等链路：Provider 先 429 后成功 -> 自动重试一次成功、进入作者确认态、出站调用 2 次、事件无失败无重复、无重复业务写入 |
| 其余 5 个真实链路测试 | `_real_provider` 帮助函数统一 `max_retries=0`（避免既有失败测试被默认重试拖慢） |

### 设计要点

- **重试白名单显式排除 `LLM_RESPONSE_INVALID`**：虽然错误注册表将
  `LLM_RESPONSE_INVALID` 标记为 `retryable=True`，但重试决策以白名单为准并显式
  排除它——结构化输出错误表明模型输出不合 schema，重试大概率重演同一缺陷。
- **重试只发生在模型出站调用层**：每次尝试发起独立 HTTP 请求，绝不重新执行
  Agent 业务逻辑，因此不会产生重复的版本/候选/Canon/事件写入；运行状态机、
  checksum、fencing token 均不受重试影响。
- **有限次数 + 指数退避**：`max_retries` 表示首次失败后的**额外**重试次数
  （默认 3），总尝试 = max_retries + 1；每次重试前休眠 base*2^n + 随机抖动。
- 认证错误（`LLM_AUTH_ERROR`）、请求被拒（`LLM_INVALID_REQUEST`/
  `LLM_ENDPOINT_NOT_FOUND`）不重试：前者重试无意义，后者放大风险。

### 验证结果

- 后端 pytest 全量：**471 passed + 6 skipped**（新增 6 项执行，含关闭重试的既有
  链路不改写；退出码 0）；
- `ruff check app tests` 通过；`mypy`（model_provider.py）通过。

### 排障记录

1. 重试链路测试断言事件序列写死为 `run_waiting_feedback`，但场景带 brief 时
   实际进入 `run_pending_clarification` → 改为稳健断言：首事件为 `run_queued`、
   无 `run_failed`、事件无重复、且无重复业务写入。
