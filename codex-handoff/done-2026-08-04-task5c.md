## 关键设计决策

1. **Canon 运行创建**：`start_canon_run` 校验 `canon_scope` 与 `run_scope` 一致；章节
   Canon 同时校验 `accepted_chapter_revision_id == chapter.accepted_chapter_revision_id`、
   `chapter_sync_status == in_sync`、`entry_handoff_status` 为有效状态（`stale` 拒绝）、
   入口 handoff 与来源版本仍匹配（`get_valid_entry`）；场景 Canon 要求
   `accepted_scene_revision_id == scene.accepted_scene_revision_id`。创建独立
   `generation_run_id` + `request_type="review"` + `decision_target="canon"` +
   `canon_source_revision_id`，入队 `run_queued` 事件 + outbox，HTTP 不回执行 LangGraph。
   Canon 运行统一使用 `request_type="review"`，不新增/持久化 `request_type="canon"`，
  Router 仍进入 CanonAgent，不调用 WritingAgent。
2. **`chapter_revision.accepted` 幂等消费者**：事件在权威的 `commit_chapter_version`
   事务边界入队（API、Worker、领域服务所有章节接受路径统一只入队一次），绝不直接调用
   CanonAgent；消费者 `handle_chapter_accepted_outbox` 先按
   `(chapter_id, accepted_chapter_revision_id)` 对消费者互斥键取事务级 advisory lock
   （`pg_advisory_xact_lock`，64 位有符号哈希键，事务提交/回滚自动释放），再查询是否已有
   Canon 运行，有则跳过（幂等），无则创建章节 Canon 运行。并发消费者被锁串行化，后到者
   在锁释放后重查见已有运行即返回，避免先 SELECT 后 INSERT 的 TOCTOU 竞态产生重复运行；
   该原子 claim 只约束消费者路径，手动 `/canon-runs` 入口不受影响（同一章节同一版本可
   多次手动创建，供测试隔离各校验子场景）。
3. **逐条决策**：`submit_canon_decisions` 按 `candidate_id` 逐条校验 `confirm|reject|defer`
   （映射为领域 `accepted|rejected|deferred`）；CAS `expected_run_version` → `claim_api_command_fence`
   （作者 `manual_command_id` + API command fence）→ CommitGuard → 内容校验 →
   `confirm_canon_decisions`（来源版本/作用域/候选类型/状态校验 + 幂等）。`canon_scope=scene`
   只保存场景作用域决策，绝不更新全局 Canon；章节级确认才生成正式结构。
4. **内容校验**：`_validate_candidate_content` 按候选类型严格校验——所有候选都必须带来源
   段落引用 `paragraph_ref`、故事内有效时间 `effective_story_time.value`、合法叙事认识状态
   `narrative_knowledge`（objective/character_belief/rumor/lie/dream/metaphor/unknown）；
   plot_thread 额外要求 `state` 或 `planned_resolution`。来源版本/作用域/类型由
   `confirm_canon_decisions` 校验。内容在 CanonAgent 提取时已校验并持久化。
5. **普通入口拒绝 canon**：既有 `start_generation_run`/`submit_run_decision` 对
   `target=canon` 抛 `CANON_NOT_ENABLED`；Canon 只走专用入口，不调用 WritingAgent。
6. **取消支持**：`CanonDecisionRequest` 追加 `decision`（默认 confirm，可 cancel）与
   `cancel_scope`（confirm|run）。`decision=cancel` 时 `candidate_decisions` 必须为空否则
   `COMMAND_CONTEXT_MISMATCH`；取消与确认一样走 CAS → `claim_api_command_fence` →
   CommitGuard → 幂等 claim。
   - `cancel_scope="confirm"`：结束本次确认，未决候选保留 pending/deferred，绝不生成
     正式 Canon，运行回到 `queued` 可后续再次确认。
   - `cancel_scope="run"`：运行转 `cancelled`，未决候选按 `(generation_run_id, scope,
     status=pending)` 原子转 `discarded`（已决策 accepted/rejected/deferred 保持不变）。
   保持 `request_type=review`、`decision_target=canon`，不修改其他任务契约。
7. **决策前候选绑定校验**：`_validate_candidate_bindings` 在 `submit_canon_decisions` 内、
   `confirm_canon_decisions` 写入之前执行，任一失败（`SCENE_STATE_INCOMPATIBLE`，重复
   ID 为 `COMMAND_CONTEXT_MISMATCH`）均不修改候选状态、正式 Canon、运行版本或写入成功
   事件：候选 ID 不得重复；候选必须存在；请求声明的 `candidate_type` 必须与候选实际
   类型一致；候选 `generation_run_id` 必须等于当前 Canon 运行 id；候选 `scope` 必须等于
   运行作用域；候选 `source_revision_id` 必须等于运行消费的 accepted 来源版本
   （`canon_source_revision_id`）；章节级候选不得带 `scene_id` 且 `chapter_id` 必须等于
   运行目标章节，场景级候选 `scene_id` 必须等于运行目标场景。
8. **最小候选规则**：`decision=confirm|reject|defer` 时 `candidate_decisions` 必须至少
   包含一条候选（否则 `COMMAND_CONTEXT_MISMATCH`）；只有 `decision=cancel` 允许空候选
   列表（`_apply_canon_cancel` 另有“取消不得携带候选”校验）。

9. API 不调用 WritingAgent（创建后仅 `queued`，无 RunDecision、无最后执行节点）。
10. 场景 Canon 运行缺/过期来源版本被拒绝。
11. 章节 Canon 创建校验 `entry_handoff_status=stale` 被拒绝（`CHAPTER_HANDOFF_CONFLICT`）。
12. 章节 Canon 创建校验 `chapter_sync_status=out_of_sync` 被拒绝（`CHAPTER_OUT_OF_SYNC`）。
13. 取消本次确认：不写正式 Canon，未决候选保留 pending，可后续再次确认成功。
14. 取消整个运行：未决候选原子转 discarded，已决策候选保持原状态，运行转 cancelled。
15. 取消请求携带 `candidate_decisions` 被拒绝（`COMMAND_CONTEXT_MISMATCH`）。
16. 取消使用 CAS（冲突 `RUN_STATE_CONFLICT`）、API command fence（`write_owner_kind=api_command`）、
    重复取消幂等（同键同请求返回同一 command_id）、同键不同请求 `IDEMPOTENCY_KEY_REUSE`。
17. `decision=confirm` 空候选列表被拒绝（`COMMAND_CONTEXT_MISMATCH`），无决策记录、运行版本
    与状态不变。
18. 候选 ID 重复被拒绝（`COMMAND_CONTEXT_MISMATCH`），无任何写入（候选保持 pending、
    CanonFact 计数为 0、运行版本/状态不变、无 RunDecision）。
19. 跨运行候选（`generation_run_id != run.id`）被拒绝（`SCENE_STATE_INCOMPATIBLE`）且无副作用。
20. 请求 `candidate_type` 与候选实际类型不一致被拒绝（`SCENE_STATE_INCOMPATIBLE`）且无副作用。
21. 候选来源版本与运行消费来源不一致被拒绝（`SCENE_STATE_INCOMPATIBLE`）且无副作用。
22. 候选目标场景与运行目标不一致被拒绝（`SCENE_STATE_INCOMPATIBLE`）且无副作用。
23. 真实双会话并发：两个独立 session/连接并发消费同一 `chapter_revision.accepted` 事件，
    只创建一个 Canon 运行（advisory lock 原子 claim 串行化）。

  领域服务所有章节接受路径统一只入队一次；不改变 5B API/状态/事件语义。

  `request_type="canon"`；Router 仍进入 CanonAgent，不调用 WritingAgent。
- 取消支持：`cancel_scope="confirm"` 运行回到 `queued`（可再次确认），`cancel_scope="run"`
  运行转 `cancelled` 且未决候选原子转 `discarded`；两者均不生成正式 Canon，不调用 WritingAgent。
- 取消与确认共用同一 `submit_canon_decisions` 入口与 `execute_command` 幂等 claim，不新增
  独立取消端点；`decision=cancel` 只允许在 `waiting_feedback` 候选已就绪时执行。
- 决策前候选绑定校验（`_validate_candidate_bindings`）与最小候选规则（confirm/reject/defer
  必须非空）都在 `confirm_canon_decisions` 写入之前完成，校验失败不产生任何数据库副作用。
- 消费者并发幂等采用事务级 advisory lock 原子 claim（`pg_advisory_xact_lock`），按
  `(chapter_id, accepted_chapter_revision_id)` 哈希键串行化并发消费者；不引入部分唯一索引，
  因此手动 `/canon-runs` 入口仍允许同一章节同一版本多次创建（既有测试依赖此行为）。
