## 关键设计决策

1. **SSE 实时透传绕开 Next.js 压缩缓冲**：Next.js 默认 `compress: true`，其压缩中间件对声明 `Accept-Encoding: gzip` 的客户端缓冲 `text/event-stream` 无限流（实测 curl 带 gzip 头 4s 仅收 10 字节、浏览器 fetch body 挂起）。修复：`compress: false` + route handler 手动 `ReadableStream` 逐块转发（文件系统路由先于 rewrites 匹配）。`Last-Event-ID` 透传后端实现断线重放。
2. **StarterKit v3 不注册 Ctrl+A**：@tiptap/starter-kit 3.29 不含 `Mod-a` keymap（@tiptap/core 的 Keymap 扩展运行时未导出），浏览器 Ctrl+A 走页面级全选，点击编辑器外按钮后 DOM selection 丢失。修复：自定义 `SelectAllKeymap`（`keymap({ "Mod-a": selectAll })`，prosemirror-keymap/commands）。
3. **选中片段多来源兜底**：`onSelectionUpdate` 异步上报 + React state 未 flush + DOM selection 在点击 focusable 按钮（mousedown→focus）时被清除 + ProseMirror state 同步延迟，导致「Ctrl+A 后立即点击续写」读不到选区。兜底读取顺序：`selectedText` state → ProseMirror state（editorRef）→ mousedown/selectionchange 捕获的 DOM selection → `window.getSelection()`。
4. **accepted 只在服务端确认后显示**：前端不凭决策响应乐观显示版本。accept 决策 → `submitRunDecision` → 响应 status=accepted 时调 `refreshSceneLatest()` 重拉版本历史；SSE `handleRunEvent` 对 `run_waiting_feedback` 解析 issues + draft/change_set 定位，随后 `getRun` 刷新快照。
5. **确定性 fixture 推进运行状态**：后端 Worker 是占位实现（不执行 LangGraph 图）。`e2e_fixtures.advance` 经领域服务 + `PostgresRunEventStore.emit` 写 `GenerationRun.status`（限定 `waiting_feedback|pending_clarification|paused`）+ 对应事件；`write_fencing_token += 1` 后同令牌写事件。事件 payload 键（issues/questions/reason）避开 `sanitize_payload` 敏感键，审校问题正文不被脱敏。
6. **决策 API 严格对应状态**：`submitRunDecision`（accept/feedback/cancel）仅 `waiting_feedback`/`pending_clarification` 可用；`resumeRun` 仅 `paused` 可用（`expected_pause_reason` 校验）。前端按钮映射同构，杜绝混用。
7. **SSE 去重与重连**：`Last-Event-ID` 记录最后成功事件 id（`run_id:sequence`），重连时后端从下一序号补发；`seen` Set 按事件 id 去重，重放与实时交叠只回调一次。
