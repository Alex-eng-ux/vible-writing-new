## 关键设计决策

1. **HTTP 只入队不执行图**：`start_generation_run` 在同一事务创建 `GenerationRun`（status=queued）+ 写 `run_queued` 事件 + outbox 入队；LangGraph 由 Worker 通过 outbox 消费者/租约领取（Task 4A 契约），请求线程不调用任何图。
2. **作者命令身份**：`submit_run_decision`/`resume_paused_run` 先由 `execute_command` 完成幂等 claim（`manual_command_id` 首次 claim 生成并复用），再 `claim_api_command_fence` 取得 `owner_kind=api_command` 的短事务 fence（切换运行写入所有者并推进 token），`source=author`、`generation_run_id=None`；不填入 Worker `LeaseContext`。
3. **CAS + 状态契约**：决策/恢复前先校验 `expected_run_version == run.run_version`（不匹配 `RUN_STATE_CONFLICT`）；`paused` 只能 resume、终态（accepted/cancelled/failed/superseded）拒绝决策、`pending_clarification` 必须用 feedback 回答（accept 拒绝）。
4. **事件序号在运行行锁内分配**：`PostgresRunEventStore.emit` 对 `GenerationRun` 行 `FOR UPDATE` 后取 `max(sequence)+1`，旧 fencing token 拒绝写入（fail-closed）。
5. **Outbox 与业务事务解耦**：业务数据先提交，`PostgresOutboxPublisher.publish` 独立调用；投递失败只把记录置为 `failed` + `last_error` + 重试时间，绝不回滚已提交业务；`FOR UPDATE SKIP LOCKED` + 唯一键 + 已 published 跳过保证重复发布幂等。
6. **SSE 重放 + 实时推送**：`GET /api/runs/{id}/events` 以 `Last-Event-ID` 头（支持 `run-id:42` 与裸 `42`）解析序号，从下一序号升序重放脱敏事件；连接建立后进入轮询循环（`_SSE_POLL_INTERVAL=1s`，独立会话 + `asyncio.to_thread`），新产生的 RunEvent 实时推送，无新事件时 heartbeat；事件 payload 经 `sanitize_payload` 脱敏，客户端按事件 `id` 去重。
7. **canon 边界**：`start_generation_run` 与 `submit_run_decision` 对 `target=canon` 抛 `CANON_NOT_ENABLED`，通用入口不接受 canon 请求。
8. **运行创建统一校验**：`start_generation_run` 创建前先 `_validate_run_create`——仅「首次 chapter + new_chapter」允许无 `plan_revision_id`（章节已有 accepted plan 时再缺省则拒绝）；其他章节/场景运行必须携带并校验当前 accepted plan（`ChapterPlanRevisionLink` 指针 + `status=accepted`）；普通运行携带 `canon_scope`/`accepted_scene_revision_id` 抛 `CANON_USE_DEDICATED_ENDPOINT`；跨章节运行校验 handoff（`get_valid_entry`）；场景基线匹配 `accepted_scene_revision_id`，章节基线匹配 `accepted_chapter_revision_id`。
9. **运行快照返回真实状态**：`run_snapshot` 从 `GenerationRun` 持久化的 `pending_node`/`pause_reason`/`clarification_questions`/`last_error_code` 读取，不再固定返回空值（Worker 在写 checkpoint/暂停时落库）。
10. **Outbox 发布租约（超时恢复）**：领取记录时置 `publishing` 并声明 `publisher_owner` + `publisher_lease_expires_at`；发布进程崩溃后记录卡在 publishing，其他发布者看到租约过期即重新领取；`publish` 的领取范围包含「pending|failed 到期」或「publishing 租约过期」两类。
11. **消费者游标先于 outbox 确认**：消费者在投递回调内先 `advance_consumer_cursor` 持久化成功游标，再返回成功由发布器确认 outbox；崩溃后重试不后退游标（幂等），`RunEventConsumerCursor.last_event_id` 扩为 String(120) 以容纳 `{run_id}:{seq}` 事件 id。
12. **严格校验跨章节入口**：`_validate_cross_chapter_entry` 按卷内 `created_at` 定位当前章的紧邻上一章——当前卷首章五个 preceding/handoff 字段必须全部为空；非首章五个字段必须全部非空，`preceding_chapter_id` 必须是当前卷紧邻上一章，来源章节版本必须是该章当前 accepted 版本，handoff 来源与链哈希必须完全匹配（`get_valid_entry`）；任一不满足抛 `CHAPTER_HANDOFF_CONFLICT`。
13. **不可变规范化运行输入信封**：`start_generation_run` 创建时把首次请求的规范化字段（`chapter_intent`/`author_feedback`/`plan_revision_id`/handoff 五字段/场景章节基线/`scene_base_revision_ids`）持久化到 `GenerationRun.normalized_input`（JSONB）；`get_run_input_envelope(run_id)` 供 Worker 仅凭 run_id 重建与首次请求完全一致的输入，重试绝不重新读取客户端输入。
14. **运行决策状态限制**：`submit_run_decision` 按决策类型各自定义允许状态——`accept` 仅 `waiting_feedback`（queued/running 不得直接 accept，防绕过 Agent 输出/等待节点）；`feedback` 仅 `waiting_feedback`/`pending_clarification`；`cancel` 允许 `queued`/`running`/`waiting_feedback`/`pending_clarification`；不满足抛 `RUN_STATE_CONFLICT`。

9. 旧 fencing token 不能写入（RunEvent emit / outbox enqueue 旧 token → `RUN_LEASE_LOST`）。
10. 消费者游标持久化/推进（`advance_consumer_cursor`/`get_consumer_cursor`）。
11. **SSE 先连接、后产生事件实时推送**：连接建立收到初始 `run:1` 后，保持连接期间 POST 决策产生 `run:2`，无需重连即可收到。
12. **运行快照返回真实状态**：`GET /runs/{id}` 返回持久化的 `pending_node`/`pause_reason`/`clarification_questions`/`last_error_code`。
13. **运行创建统一校验**：场景运行缺 `plan_revision_id`、`chapter continue` 缺 `plan_revision_id`、携带 `canon_scope`、`plan_revision_id` 非当前 accepted plan 均被拒绝（对应错误码）。
14. **publishing 租约超时恢复**：卡在 publishing 的过期记录可被新发布者重新领取并发布；未过期租约不被重复领取。
15. **消费者游标先于 outbox 确认**：崩溃重试后 outbox 由 failed 转 published 且游标不后退（幂等，`attempt_count` 递增）。
16. **跨章节入口严格校验**：首章携带 preceding 字段、非首章缺字段、错前置章节、来源版本非当前 accepted、源章节 accepted 指针推进后旧 handoff 失效均被拒绝（`CHAPTER_HANDOFF_CONFLICT`）；前置字段完全正确才成功。
17. **不可变规范化运行输入**：`get_run_input_envelope` 返回与首次请求一致的 `chapter_intent`/`author_feedback`/`run_scope`/`request_type`/`decision_target`/`scene_base_revision_ids`；修改返回副本不影响持久化输入。
18. **决策状态限制**：queued 不能直接 accept/feedback、running 不能直接 accept（均 `RUN_STATE_CONFLICT`）；`waiting_feedback` 才允许 accept（成功）。
