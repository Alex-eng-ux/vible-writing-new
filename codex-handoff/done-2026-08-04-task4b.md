## 复核修复汇总（按轮次）

### 首轮修复（Codex 复核问题）

1. **章节分支接入实际 LangGraph**：新增 `chapter_graph.py`，编译真实 `StateGraph`
   （ChapterPlanner -> ChapterReview -> ChapterAggregator），用 `AgentCallable` +
   `AgentResultRouter`，`thread_id` + checkpointer 断点续跑，`_pause_node` 用
   `interrupt` 等待 accept / feedback / cancel。
2. **允许无 accepted 章节版本的新章节首轮聚合**：`compute_aggregation_eligibility`
   无 accepted 指针时返回 `FIRST_ROUND_CAPABLE`。
3. **去掉 entry_handoff_valid 布尔**：改接收 `entry_handoff_id` /
   `entry_source_chapter_revision_id` / `entry_handoff_chain_hash`；新增
   `valid_entry_handoff` 校验真实 handoff + 来源 accepted + 当前指针。
4. **禁止按最新行推断 accepted**：`Chapter`/`Scene` 加显式 accepted 指针 + 迁移
   `a2b3c4d5e6f7` + 回填；commit 函数写指针。
5. **handoff 失效一次调用递归 C1→C2→C3**：`invalidate_downstream_handoffs` 改 BFS
   递归，并把受影响下游章节置 `out_of_sync`。

### 二次修复（Codex 复核问题）

1. **interrupt 恢复回到 pending_node**：`_route_after_pause` 按 `_pause_action`
   路由；`state` 新增 `_pause_action`。
2. **handoff 读取用显式指针**：`handoff._current_accepted_revision_id` 改用
   `Chapter.accepted_chapter_revision_id`。
3. **跨章节 handoff 用来源章节指针校验**：`get_valid_entry` / `valid_entry_handoff`
   比较来源修订章节的 accepted 指针，不再与目标章比较。
4. **聚合节点传递并校验 Worker fencing token**：聚合节点从信封传
   `lease_worker_id/lease_fencing_token/write_fence_*`；`chapter_aggregator` 写前
   走 `CommitGuard.validate`；旧 token 返回 `RUN_LEASE_LOST` 且不写入。

### 三次修复（Codex 复核问题）

   `last_durable_node` 再清空；`_route_after_pause` 回到 `last_durable_node`，
   同一次 resume 即进入审校。测试
   `test_chapter_graph_resume_accept_returns_to_pending_node`。
